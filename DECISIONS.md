# Architectural Decisions

## What was built

- **Idempotent webhook ingestion (`POST /webhooks/pigeon`)**: Captures raw request bytes via `express.raw()` before JSON parsing so HMAC-SHA256 verification (`t=<unix>,v1=<hex>`) matches the exact wire payload. Rejects forged or stale (`> 300s`) signatures with `401`, malformed JSON with `400`, and unknown workspaces/event types/unknown message statuses with `200`. Inbound messages deduplicate via unique `(workspace, messageId)` index in MongoDB and sort deterministically by `(occurredAt, messageId)`.
- **Durable outbox & multi-instance rate limiting**: Outbound replies (`POST /__grader/reply` and `POST /api/conversations/:contact/reply`) share `enqueueReply()`, persisting atomically to `outbound_messages` keyed by unique `(workspace, clientRef)` and returning `202` before contacting Pigeon. `OutboxWorker` claims queued work with an 18-second MongoDB lease (`leaseOwner`, `leaseUntil`), uses `Idempotency-Key: clientRef` on every `POST /v1/messages`, coordinates per-workspace send rate across instances via a Redis Lua token bucket + shared `ratelimit:cooloff:<workspace>` (`Retry-After`) and `outage:cooloff:<workspace>` keys, and only transitions `queued -> sent` so late HTTP responses never overwrite an already-received `delivered` webhook.
- **Atomic conversation ownership**: `claimConversation()` uses an atomic MongoDB `findOneAndUpdate` with `{ workspace, contact, $or: [{ assignee: null }, { assignee: agent }] }` and upsert, catching `E11000` conflicts to return `409` cleanly under concurrent claims.
- **OIDC PKCE auth & multi-instance WebSockets**: Implemented OIDC discovery, PKCE (`S256`), RS256 `id_token` verification via Node `crypto`, and MongoDB-persisted sessions (`sessions` collection). `POST /__grader/reset` clears application collections and non-session Redis keys while preserving `sessions` and `session:*`/`sess:*`. WebSockets (`/ws?workspace=<id>&after=<seq>`) validate the session cookie and workspace membership during HTTP upgrade, subscribe to Redis Pub/Sub before querying MongoDB `events` (`seq > after`), and deduplicate by `seq`.
- **React frontend**: Built a two-pane shared inbox in `scaffold/web` supporting OIDC sign-in, workspace switching, open/closed filters, pagination, claim/release, close/reopen, replies with live status updates, and private agent notes.

## Trade-offs, assumptions, and what is still incomplete

- **End-to-end encrypted private notes (`PROTOCOL.md`)**: Private notes are encrypted client-side in `scaffold/web/src/crypto.ts` (`AES-256-GCM` with per-note IV and `${workspace}:${contact}` AAD) before hitting `POST /api/conversations/:contact/notes`, so the server only stores opaque `ciphertext`, `iv`, `alg`, and `keyId`. Agents share/enter the workspace key out-of-band via the Settings modal (`localStorage`).
- **Search**: `GET /api/search?workspace=<id>&q=...` provides workspace-scoped search over inbound and outbound messages using MongoDB so it works reliably even when optional Elasticsearch is skipped on machines with < 7.5 GB RAM. Encrypted notes are intentionally excluded from server search.
- **Billing**: Bonus Paybox per-seat billing was not implemented.
- **Local runtime verification**: Unit and integration tests run against an in-memory MongoDB/Redis test harness (`scaffold/server/test/`) because Docker Desktop / MongoDB / Redis are not running in the current local environment; `npm run check` / `npm run check:full` has not yet been executed against live Docker containers.
